4. بروزرسانی IOS با TFTP

TFTP روی UDP پورت 69 کار می‌کند. کامپیوتر TFTP Server (مثل Tftpd64) باید با سوئیچ در یک Subnet باشد، فایل IOS داخل پوشه Root سرور قرار بگیرد و Firewall کامپیوتر هنگام انتقال خاموش یا مجاز شود.

۱) آماده‌سازی و بک‌آپ

show version
show flash:
ping 192.168.1.100

copy running-config tftp:
copy flash:c2960-lanbasek9-mz.150-2.SE11.bin tftp:

در show version نسخه فعلی و در show flash: فضای خالی را ببین؛ باید جای کافی برای Image جدید وجود داشته باشد. اگر جا نیست، Image قدیمی را با delete flash:نام-فایل حذف کن (بعد از گرفتن بک‌آپ).

۲) کپی Image جدید

copy tftp: flash:
Address or name of remote host []? 192.168.1.100
Source filename []? c2960-lanbasek9-mz.152-7.E9.bin
Destination filename [c2960-lanbasek9-mz.152-7.E9.bin]?   (Enter)

verify /md5 flash:c2960-lanbasek9-mz.152-7.E9.bin

اگر فایل به‌صورت .tar است، به‌جای copy از دستور زیر استفاده کن که خودش Extract و نصب می‌کند:

archive download-sw /overwrite tftp://192.168.1.100/c2960-lanbasek9-tar.152-7.E9.tar

۳) انتخاب Image برای Boot و Reload

configure terminal
boot system flash:c2960-lanbasek9-mz.152-7.E9.bin
end
write memory
reload

۴) بررسی

show version
show boot
در زمان کپی، برق یا کابل را قطع نکن. حتماً قبل از Reload، MD5 فایل را با مقدار سایت سیسکو مقایسه کن و Image قبلی را تا مطمئن‌شدن از سالم‌بودن نسخه جدید نگه دار.
حفظی: بک‌آپ → کپی با copy tftp: flash: → verify /md5 → boot system → reload

5. ریست کردن سوئیچ (پاک‌کردن کانفیگ)

برای برگرداندن سوئیچ به حالت کارخانه باید هم Startup-Config و هم اطلاعات VLAN پاک شود.

enable
write erase
delete flash:vlan.dat
reload

دستورات پاک‌کردن کانفیگ (هر سه معادل‌اند)

write erase
erase startup-config
erase nvram:

Erasing the nvram filesystem will remove all configuration files! Continue? [confirm]

هر سه فقط Startup-Config را پاک می‌کنند. اطلاعات VLAN جداگانه در vlan.dat ذخیره است و با delete flash:vlan.dat پاک می‌شود. روی بعضی پلتفرم‌ها (مثل روترها) erase /all nvram: همه فایل‌های NVRAM را پاک می‌کند.

در طول مراحل:

  • روی delete دو بار Confirm می‌خواهد (نام فایل و تأیید حذف).
  • هنگام reload اگر پرسید «System configuration has been modified. Save?» جواب no بده، وگرنه کانفیگ فعلی دوباره ذخیره می‌شود.
  • سپس Confirm برای Reload را بزن.

بررسی بعد از بالا آمدن

show startup-config
show vlan brief
show running-config

باید پیام startup-config is not present بیاید و فقط VLANهای پیش‌فرض (1 و 1002 تا 1005) دیده شوند.

پاک‌کردن کانفیگ، Running-Config را فوراً تغییر نمی‌دهد؛ تا قبل از Reload همه تنظیمات فعال می‌ماند. بین write erase و reload دستور write memory نزن.
حفظی: write erase → delete flash:vlan.dat → reload (روی Save جواب no)
بخش ۲ — Switching

6. VLAN، Trunk و Inter-VLAN

VLAN شبکه را در لایه ۲ به چند Broadcast Domain جدا تقسیم می‌کند و معمولاً هر VLAN یک Subnet مجزا دارد.

vlan 10
 name Sales
interface fa0/2
 switchport mode access
 switchport access vlan 10

interface g0/1
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk native vlan 99
 switchport trunk allowed vlan 10,20,99

دستور switchport trunk encapsulation dot1q فقط روی سوئیچ‌هایی لازم است که ISL را هم پشتیبانی می‌کنند. در 802.1Q، ترافیک Native VLAN بدون Tag ارسال می‌شود.

Router-on-a-Stick

interface g0/0
 no shutdown
interface g0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface g0/0.99
 encapsulation dot1Q 99 native

سوئیچ Layer 3 (SVI)

ip routing
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown

بررسی

show vlan brief
show interfaces trunk
show interfaces g0/1 switchport
Native VLAN دو سر Trunk باید یکسان باشد؛ در غیر این صورت هشدار mismatch می‌دهد و ترافیک به VLAN اشتباه می‌رود.

7. STP — اولویت‌بندی

انتخاب Root Bridge

کمترین Bridge ID انتخاب می‌شود.

Bridge ID = Priority + MAC Address

پس اول Priority و در صورت برابر بودن MAC بررسی می‌شود.

انتخاب Root Port

  1. کمترین Root Path Cost
  2. کمترین Sender Bridge ID
  3. کمترین Sender Port ID

انتخاب Designated Port

  1. کمترین Root Path Cost
  2. کمترین Bridge ID
  3. کمترین Port ID
حفظی: Root Bridge → Root Port → Designated Port → Blocked Port

برای Root Bridge: Priority ↓ → MAC ↓

Priority پیش‌فرض STP معمولاً 32768 است.

8. STP — تکمیلی (RSTP، PortFast، BPDU Guard)

Bridge ID واقعی = Priority + VLAN ID (Extended System ID) + MAC؛ برای همین Priority پیش‌فرض VLAN 1 برابر 32769 دیده می‌شود. Priority فقط مضرب 4096 است.

سرعت لینکSTP Cost
10 Mbps100
100 Mbps19
1 Gbps4
10 Gbps2
نسخهوضعیت پورت‌ها
STP (802.1D)Blocking → Listening → Learning → Forwarding (حدود 30 تا 50 ثانیه)
RSTP (802.1w)Discarding / Learning / Forwarding؛ نقش‌های Alternate و Backup اضافه می‌شوند و همگرایی سریع است
spanning-tree mode rapid-pvst
spanning-tree vlan 1 root primary
spanning-tree vlan 1 priority 4096

interface fa0/1

show spanning-tree
show spanning-tree vlan 1
show spanning-tree summary
PortFast فقط برای پورت‌های End Device. BPDU Guard با دریافت BPDU روی پورت PortFast، آن را Err-Disabled می‌کند.

9. EtherChannel

EtherChannel چند لینک فیزیکی را به یک لینک منطقی تبدیل می‌کند. مزایا: افزایش پهنای باند، Redundancy و جلوگیری از Block شدن لینک‌های اضافی توسط STP.

روشپروتکلحالت‌ها
LACPIEEE 802.3adactive / passive
PAgPCiscodesirable / auto
Staticبدون پروتکلon

LACP

! SW1
conf t
interface range fa0/1 - 2
 channel-group 1 mode active
 exit
interface port-channel 1
 switchport mode trunk
 exit
! SW2
conf t
interface range fa0/1 - 2
 channel-group 1 mode active
 exit
interface port-channel 1
 switchport mode trunk
 exit

LACP: active↔active یا active↔passive. حالت passive↔passive تشکیل نمی‌شود.

PAgP

interface range fa0/1 - 2
 channel-group 1 mode desirable

PAgP: desirable↔desirable یا desirable↔auto. auto↔auto تشکیل نمی‌شود.

Static

interface range fa0/1 - 2
 channel-group 1 mode on

پورت‌های عضو EtherChannel باید تنظیمات سازگار داشته باشند؛ مثل Speed، Duplex، Access/Trunk، Native VLAN و Allowed VLAN.

بررسی

show etherchannel summary
show interfaces port-channel 1
show lacp neighbor
حفظی: LACP = active/passive | PAgP = desirable/auto | Static = on

10. PoE (Power over Ethernet)

PoE تغذیه دستگاه‌هایی مثل IP Phone، Access Point و دوربین را از طریق همان کابل شبکه انجام می‌دهد. سوئیچ نقش PSE (منبع) و دستگاه نقش PD (مصرف‌کننده) را دارد. فقط مدل‌های PoE سوئیچ این قابلیت را دارند.

استانداردنامتوان خروجی PSE
802.3afPoE15.4 W
802.3atPoE+30 W
802.3btPoE++60 W / 90 W
Cisco UPOEاختصاصی60 W

تنظیم

interface fa0/5
 power inline auto
 power inline auto max 15400
 power inline static max 15400
 power inline never
  • auto: پیش‌فرض؛ سوئیچ PD را شناسایی می‌کند و برق می‌دهد.
  • static: توان را از Budget برای آن پورت رزرو می‌کند.
  • never: PoE روی پورت خاموش است.
  • max: سقف توان پورت به میلی‌وات.

بررسی

show power inline
show power inline fa0/5
show power inline detail

در خروجی show power inline موارد Admin (auto/off)، Oper (on/off/faulty/power-deny)، توان مصرفی، نوع دستگاه و Class دیده می‌شود. بالای جدول هم Available، Used و Remaining مربوط به Budget کل سوئیچ نمایش داده می‌شود.

اگر Oper برابر power-deny بود، Budget سوئیچ کافی نیست. اگر faulty بود، کابل یا خود دستگاه مشکل دارد.
مراحل PoE: Detection → Classification → Power-Up. توان مصرفی دقیق معمولاً با CDP یا LLDP-MED بین سوئیچ و PD مذاکره می‌شود.

13. OSPF در حد CCNA

OSPF یک Dynamic Routing Protocol است.

راه‌اندازی

router ospf 1
 router-id 1.1.1.1
 network 192.168.1.0 0.0.0.255 area 0
 network 10.0.0.0 0.0.0.3 area 0

عدد 1، Process ID است و الزاماً Router ID نیست.

روتر دوم

router ospf 1
 router-id 2.2.2.2
 network 192.168.2.0 0.0.0.255 area 0
 network 10.0.0.0 0.0.0.3 area 0

بررسی

show ip ospf neighbor
show ip route ospf
show ip ospf
show ip protocols

Neighbor صحیح معمولاً در وضعیت FULL است. Routeهای OSPF با حرف O نمایش داده می‌شوند.

OSPF Message Types

شمارهMessageکاربرد
1Helloپیدا کردن و حفظ Neighbor
2DBDخلاصه LSDB
3LSRدرخواست LSA موردنیاز
4LSUارسال LSA
5LSAckتأیید دریافت LSA
حفظی: Hello → DBD → LSR → LSU → LSAck

انتخاب Router ID

  1. Router-ID دستی با router-id x.x.x.x
  2. بالاترین IP روی Loopback
  3. اگر Loopback وجود نداشت، بالاترین IP Interface فعال

14. OSPF — تکمیلی (DR/BDR، Cost، Passive)

شرط Neighbor شدن

  • Area، Subnet/Mask، Hello/Dead Timer و MTU یکسان
  • Router ID یکتا و Authentication یکسان

Timer پیش‌فرض در شبکه Broadcast و Point-to-Point برابر Hello 10 و Dead 40 ثانیه است.

DR / BDR

در شبکه Multi-Access مثل Ethernet، یک DR و یک BDR انتخاب می‌شود. معیار: بالاترین Priority (پیش‌فرض 1) و بعد بالاترین Router ID. انتخاب Non-Preemptive است و Priority = 0 هرگز DR نمی‌شود. DROtherها با هم در وضعیت 2-Way می‌مانند که طبیعی است.

آدرس‌ها: 224.0.0.5 برای همه روترهای OSPF و 224.0.0.6 برای DR/BDR.

Cost و دستورات کاربردی

Cost = Reference Bandwidth ÷ Bandwidth (پیش‌فرض 100 Mbps، پس Fa و Gig هر دو Cost 1 می‌گیرند).

router ospf 1
 auto-cost reference-bandwidth 1000
 passive-interface g0/0

interface g0/1
 ip ospf priority 100
 ip ospf network point-to-point
 ip ospf cost 10
حفظی وضعیت Neighbor: Down → Init → 2-Way → ExStart → Exchange → Loading → Full

16. EIGRP در حد CCNA

EIGRP = Enhanced Interior Gateway Routing Protocol

  • Advanced Distance Vector
  • از DUAL استفاده می‌کند.
  • Metric اصلی بر اساس Bandwidth و Delay است.
  • AD داخلی = 90
  • AD خارجی = 170
  • Route Code = D

راه‌اندازی

router eigrp 100
 network 192.168.1.0 0.0.0.255
 network 10.0.0.0 0.0.0.3

عدد 100، AS Number است و روترهای EIGRP برای Neighbor شدن باید AS یکسان داشته باشند.

بررسی

show ip eigrp neighbors
show ip route eigrp
show ip eigrp topology

مفاهیم مهم

  • Successor: بهترین مسیر
  • Feasible Successor: مسیر پشتیبان Loop-Free
  • Feasible Distance (FD): بهترین Metric محاسبه‌شده
  • Reported Distance (RD): Metric اعلام‌شده توسط Neighbor
DUAL: Best Path → Successor | Backup Path → Feasible Successor

Message Types

Messageکاربرد
Helloپیدا کردن و حفظ Neighbor
Updateارسال اطلاعات Route
Queryپرسیدن مسیر از Neighborها
Replyپاسخ به Query
ACKتأیید دریافت پیام‌های قابل‌اعتماد
حفظی: Hello → Update → Query → Reply → ACK

Default Route در EIGRP

ip route 0.0.0.0 0.0.0.0 10.0.0.2

router eigrp 100
 redistribute static

no auto-summary

router eigrp 100
 no auto-summary

این دستور مربوط به رفتار قدیمی EIGRP است. در IOSهای جدید معمولاً Auto-Summarization به‌صورت پیش‌فرض انجام نمی‌شود و لازم نیست در هر کانفیگ آن را اضافه کرد.

18. ACL در حد CCNA

ACL = Access Control List

برای Permit/Deny کردن ترافیک استفاده می‌شود.

Standard ACL

فقط Source IP را بررسی می‌کند.

access-list 10 deny host 192.168.10.10
access-list 10 permit any

Extended ACL

Source IP + Destination IP + Protocol + Port را بررسی می‌کند.

مثال: جلوگیری از HTTP شبکه VLAN 10 به سرور 192.168.100.20:

access-list 100 deny tcp 192.168.10.0 0.0.0.255 host 192.168.100.20 eq 80
access-list 100 permit ip any any

اعمال ACL روی Interface

interface g0/0
 ip access-group 100 in

in: ترافیک وارد Interface می‌شود.

out: ترافیک از Interface خارج می‌شود.

Named ACL

ip access-list extended BLOCK-HTTP
 deny tcp 192.168.10.0 0.0.0.255 host 192.168.100.20 eq 80
 permit ip any any
 exit

interface g0/0
 ip access-group BLOCK-HTTP in

نکات مهم

  • ACL از بالا به پایین بررسی می‌شود.
  • اولین Rule که Match شود اجرا می‌شود.
  • در انتهای ACL یک Implicit Deny وجود دارد.
  • Standard ACL → فقط Source IP
  • Extended ACL → Source + Destination + Protocol + Port
حفظی CCNA: Standard نزدیک مقصد، Extended نزدیک مبدأ.

19. NAT در حد CCNA

NAT = Network Address Translation

تبدیل IPهای Private به Public و برعکس.

انواع NAT

نوعتوضیح
Static NATیک Private ↔ یک Public
Dynamic NATPrivate → Pool از Public IPها
PAT / NAT Overloadچند Private → یک Public با Port Number

Static NAT

interface g0/0
 ip address 192.168.1.1 255.255.255.0
 ip nat inside
 no shutdown

interface g0/1
 ip address 203.0.113.1 255.255.255.0
 ip nat outside
 no shutdown

ip nat inside source static 192.168.1.10 203.0.113.10

Dynamic NAT

access-list 1 permit 192.168.1.0 0.0.0.255

ip nat pool PUBLIC 203.0.113.10 203.0.113.20 netmask 255.255.255.0

ip nat inside source list 1 pool PUBLIC

interface g0/0
 ip nat inside

interface g0/1
 ip nat outside

PAT

access-list 1 permit 192.168.1.0 0.0.0.255

interface g0/0
 ip nat inside

interface g0/1
 ip nat outside

ip nat inside source list 1 interface g0/1 overload

overload = PAT

بررسی NAT

show ip nat translations
show ip nat statistics
clear ip nat translation *
حفظی: Static = 1:1 | Dynamic = Pool | PAT = Many-to-One + Port
بخش ۵ — Redundancy و WAN

20. FHRP — HSRP

HSRP یک Gateway مجازی بین دو روتر می‌سازد تا با خرابی یکی، کلاینت‌ها قطع نشوند. روتر با بالاترین Priority (پیش‌فرض 100) می‌شود Active و دیگری Standby.

interface g0/0
 ip address 192.168.1.2 255.255.255.0
 standby 1 ip 192.168.1.1
 standby 1 priority 110
 standby 1 preempt
show standby brief

Default Gateway کلاینت‌ها باید IP مجازی (192.168.1.1) باشد. HSRP اختصاصی Cisco است؛ VRRP استاندارد باز است و GLBP علاوه بر Redundancy، Load Balancing هم انجام می‌دهد.

21. GRE Tunnel در حد CCNA

GRE = Generic Routing Encapsulation

GRE یک Tunnel منطقی بین دو روتر ایجاد می‌کند. GRE خودش رمزنگاری نمی‌کند؛ برای Encryption معمولاً GRE over IPsec استفاده می‌شود.

مثال

R1 WAN = 10.0.0.1، R2 WAN = 10.0.0.2 و IPهای Tunnel برابر 172.16.1.1 و 172.16.1.2.

R1

conf t

interface tunnel 0
 ip address 172.16.1.1 255.255.255.252
 tunnel source 10.0.0.1
 tunnel destination 10.0.0.2
 no shutdown

R2

conf t

interface tunnel 0
 ip address 172.16.1.2 255.255.255.252
 tunnel source 10.0.0.2
 tunnel destination 10.0.0.1
 no shutdown

تست:

ping 172.16.1.2

اجرای OSPF روی GRE

router ospf 1
 network 172.16.1.0 0.0.0.3 area 0

بررسی

show interface tunnel 0
show ip interface brief
حفظی: GRE = Tunnel | IPsec = Encryption

22. Port Security

Port Security روی پورت Access فعال می‌شود تا فقط MAC Addressهای مجاز بتوانند از پورت استفاده کنند.

فعال‌سازی

interface fa0/1
 switchport mode access
 switchport port-security

حداکثر تعداد MAC

switchport port-security maximum 1

MAC دستی

switchport port-security mac-address aaaa.bbbb.cccc

Sticky MAC

switchport port-security mac-address sticky

Violation Mode

Modeرفتار
Shutdownپورت را Err-Disabled می‌کند
Restrictترافیک MAC غیرمجاز Drop و Violation ثبت می‌شود
Protectترافیک MAC غیرمجاز Drop می‌شود

مثال کامل:

interface fa0/1
 switchport mode access
 switchport port-security
 switchport port-security maximum 1
 switchport port-security mac-address sticky
 switchport port-security violation shutdown

بررسی

show port-security
show port-security interface fa0/1
show port-security address
حفظی: Access Port → Maximum MAC → Allowed MAC → Violation

23. امنیت Layer 2 (DHCP Snooping و DAI)

این مکانیزم‌ها روی سوئیچ جلوی حملات مبتنی بر DHCP و ARP را می‌گیرند.

DHCP Snooping

ip dhcp snooping
ip dhcp snooping vlan 10
interface g0/1
 ip dhcp snooping trust

فقط پورت Trusted (سمت سرور/Uplink) اجازه ارسال Offer و Ack دارد؛ جلوی Rogue DHCP Server را می‌گیرد و Binding Table می‌سازد.

Dynamic ARP Inspection

ip arp inspection vlan 10
interface g0/1
 ip arp inspection trust

DAI پیام‌های ARP را با Binding Table مقایسه می‌کند و جلوی ARP Spoofing را می‌گیرد.

show ip dhcp snooping binding
show ip arp inspection
